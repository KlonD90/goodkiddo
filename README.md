# GoodKiddo

Личный ИИ-ассистент в Telegram: поручения и напоминания в личке, организация встреч в группах. Пре-альфа `0.2.0-prealpha.1`.

Один агент использует инструменты и сохраняет контекст каждого чата. Напоминания, сбор ответов и дедлайны встреч живут в SQLite; для их доставки повторный вызов модели не нужен.

## Сценарии

**В личке** можно поручить найти и сравнить варианты, получить короткий отчёт со ссылками или написать: «Напомни завтра в 10:00 позвонить». Для свежих источников подключается Brave Search. Без поискового ключа бот объясняет ограничение и работает с предоставленными данными.

**Мини-страницы**: «Создай мини-страницу с планом поездки». При включённой публикации бот создаёт адаптивный HTML/CSS и возвращает ссылку `https://whosagoodkiddo.me/p/…`, срок действия и ID. Страница доступна любому обладателю ссылки до 24 часов. Можно попросить список публикаций или отозвать свою по ID. Можно также попросить браузерную ссылку на конкретную папку: навигация, безопасный preview текста/изображений, скачивание и отдельное открытие HTML с выбранными локальными CSS/изображениями/шрифтами. Это неизменяемые статические копии; корень VFS, JavaScript, формы и внешние загрузки отключены. Черновик сохраняется файлом без публикации. Настройка и передача для production: [docs/mini-pages-restoration.md](docs/mini-pages-restoration.md).

**В группе** позовите бота по username или ответьте на его сообщение: «Собери ужин: пятница 19:00 или суббота 18:00, ответы до четверга 20:00». Агент уточнит недостающие параметры, затем создаст кнопки выбора времени. Можно выбрать несколько вариантов, снять выбор повторным нажатием или отметить, что ничего не подходит.

Если при создании явно указаны @username участников, напоминание перечислит тех, кто ещё не ответил. Без списка это открытая встреча и общее напоминание в группе. По умолчанию напоминание отправляется в середине периода сбора ответов, если до дедлайна более 20 минут. К дедлайну бот вернётся с подсчётом голосов, отсутствующими ответами и указанием ничьей. Бронирования не выполняются.

## Запуск

Требуется Bun 1.3+. Установите зависимости через `bun install`, заполните `.env` по [configuration settings](src/config/assistant-config.ts), затем используйте `bun run dev` или `bun run build` и `bun start`.

Обязательны `TELEGRAM_BOT_TOKEN`, `LLM_BASE_URL`, `LLM_API_KEY`, `LLM_MODEL`. URL должен заканчиваться на путь до `/chat/completions`, например `https://provider.example/v1`. Модель должна поддерживать function tools. Провайдер пока не выбран: подключение и тарифы задаются конфигурацией.

При старте читается `.env`. Публичные чаты регистрируются автоматически при обращении к боту; ручная регистрация старого setup не требуется. Основной запуск использует `src/app/telegram-assistant.ts`. Сборка и проверка кода не запускают сервисы автоматически.

## Управление

- `/start`, `/help` — возможности, примеры и ссылка добавления бота в группу.
- `/timezone Europe/Moscow` — часовой пояс чата; в группе доступно администратору. Уже сохранённые моменты времени не сдвигаются.
- `/tasks` — активные напоминания и встречи.
- `/cancel ID` — отмена своей задачи.
- `/cancel_voice` — отмена своего текущего распознавания голоса.
- `/clear` — удаление контекста беседы; в группе доступно администратору. Запланированные задачи сохраняются.
- `/privacy` — краткое описание обработки данных.

Бот реагирует на обращения, команды и ответы на свои сообщения. Чужие разговоры в группе не добавляются в контекст даже при выключенном privacy mode. Нативные опросы пока не используются: сбор доступности реализован inline-кнопками Telegram и текстовыми ответами на сообщения бота. Личные сообщения участникам от имени организатора не отправляются.

## Ограничения расходов и данные

Число вызовов модели на поручение, число поисков, дневные лимиты пользователя/чата и количество активных задач настраиваются. Месячный бюджет резервируется перед каждым вызовом и уточняется по usage. При неоднозначном сетевом сбое сохраняется консервативная оценка. Укажите действительные тарифы; лимит провайдера остаётся отдельной настройкой его аккаунта.

PostHog включается через `POSTHOG_PROJECT_KEY` и постоянный `ANALYTICS_SALT`. Аналитика содержит только события, счётчики и HMAC-идентификаторы. Тексты, имена и Telegram username в PostHog не отправляются. Локальная база содержит контекст и данные задач, поэтому её следует хранить как приватные данные.

Голосовые подключаются отдельно через `ENABLE_VOICE_MESSAGES=true` и существующий `TRANSCRIPTION_API_KEY` OpenAI. Используется `whisper-1`; нужен установленный FFmpeg. До подключения ключа голос выключен. Жёсткий общий бюджет распознавания — максимум **$5 в календарный месяц Asia/Tbilisi**, с постоянными резервами SQLite до вызова API; его можно уменьшить. Вход ограничен 1 МиБ и 120 секундами, дневными квотами и таймаутами. Расшифровка проходит как обычный запрос от исходного автора в исходном чате, ответ приходит текстом. Аудио не сохраняется ботом; OpenAI получает ограниченный WAV, PostHog — только отметку вида входа. Подробнее: [docs/telegram-voice.md](docs/telegram-voice.md).

Подробности реализации и известные ограничения: [docs/telegram-assistant.md](docs/telegram-assistant.md).

## Разработка

Новый путь не запускает Tribunal, Discord, SDK-раннеры или Docker. Историческая реализация сохранена: `bun run dev:legacy`, `bun run build:legacy`, `bun run start:legacy`. Старый setup относится к ней. Прежние настройки находятся в [legacy configuration](src/config/config.ts), описание — в [docs/legacy-readme.md](docs/legacy-readme.md).
