# Web, media, and Telegram restoration checkpoint

This branch is an independent initial checkpoint based on `455e5be`. No production, service, credential, original-checkout, or coordinator-worktree changes were made. Runtime integration is deliberately left to the coordinator because its file/state workers own the shared modules.

## Implemented and tested modules

- `providers/public-url-policy.ts`, `assistant-page.ts`: public HTTP/HTTPS reading, canonical URL validation, standard ports, no credentials, all DNS answers checked, socket pinned to a validated address, redirects revalidated (3 maximum), 15-second deadline, 2 MiB response cap, 20,000-character output. No browser execution, cookies, auth headers, proxy, or compressed responses. HTML scripts/forms/navigation are removed. Results explicitly marked untrusted.
- `assistant/web-tools.ts`: `read_url` definition and dispatcher, three reads per tool context, independent of Brave or a paid-search allowance.
- `capabilities/documents/`: generic in-memory `extractAttachment({ filename, mimeType, bytes, signal })`. PDF uses `pdf-parse` (50-page prefix), CSV uses `csv-parse` (quoted/multiline comma/semicolon/tab data), XLSX uses ExcelJS (10 sheets, 200 rows per sheet, 20 columns). Formulas are preserved as text, never evaluated. Output capped at 20,000 characters and input at 10 MiB. XLSX ZIP entries are checked with yauzl against both declared and actual expanded size (32 MiB/1000 entries). Parsing executes trusted code in a worker that is terminated on cancellation or a 15-second deadline.
- `assistant/attachment-tools.ts`: `extract_file` definition plus adapter to the file worker's `get(chatId, path)` interface. It never accepts a host filesystem path or another chat ID.
- `providers/assistant-stream.ts`: bounded SSE parser; UTF-8/chunk boundaries, fragmented tool calls, usage, terminal-event validation. Only `delta.content` reaches preview callbacks. Hidden reasoning is discarded. A truncated stream fails instead of being treated as a finished reply.
- `providers/assistant-llm.ts`: optional fourth `onContent` callback and fifth `images` argument; `stream:true` and usage reporting when callback supplied. Omits Authorization when the configured key is empty. The nonstreamed result also strips extra provider fields.
- `providers/assistant-vision.ts`: validated PNG/JPEG/WebP data URL parts, 5 MiB per image, at most two per request, attaches to the last user message without mutating stored history.
- `channels/telegram-rich-delivery.ts`: final native `sendRichMessage` with exactly `{ markdown }`, including GFM tables; escapes raw HTML and removes Markdown media embedding to avoid unintended remote fetches. Only a definitive 404 triggers plain fallback; uncertain failures propagate. Group preview creation/edit primitives are available.
- `channels/telegram-draft-stream.ts`: private-only draft snapshots, same nonzero draft ID, roughly one second between calls, coalescing, serialized requests, and 429 `retry_after` handling. Closing waits for any in-flight preview and never sends the durable final message.

Dependencies pinned in `package.json`/`bun.lock`: csv-parse 6.2.1, pdf-parse 2.4.5, ExcelJS 4.4.0, yauzl 3.2.0, ipaddr.js 2.2.0, cheerio 1.2.0; @types/yauzl 2.10.3. Package scripts were disabled during installation. No legacy `xlsx@0.18.5` was added.

Validation: `bun run typecheck`; targeted Vitest suite, 37 passing synthetic tests; `bun run build`. Tests include a generated text PDF and workbook, corrupt input, oversized files, cancellation, mixed/private DNS answers, redirects to metadata addresses, hidden reasoning, fragmented tool calls, draft throttling/flood waits, and uncertain-delivery fallback behavior. No live Telegram message was sent.

## Provider evidence

Public no-auth `space-bunny-free` accepted image data URLs and SSE and completed both synthetic requests. A 512x512 green square was correctly described as `Green`; a 32x32 green square was incorrectly described as `Black`. Transport support is established, image quality is not guaranteed. See `evidence/provider-smoke-summary.json`; raw reasoning was discarded and no real user content was sent.

The official model registry advertises text/image/video input and text output, with tools and zero token pricing: <https://github.com/anomalyco/models.dev/blob/dev/providers/opencode/models/space-bunny-free.toml>. Audio is not advertised. Voice transcription was not tested and remains unsupported by this checkpoint. Do not silently select Whisper, a paid provider, a new key, or an audio endpoint. A future configured transcription adapter must accept bounded in-memory bytes and be enabled only after its actual endpoint/model and budget are verified.

## Remaining safety and functionality limits

- This checkpoint is modules plus tested provider enhancement, not a fully wired active runtime. Complete the wiring above and run integration tests before deployment.
- Legacy XLS is explicitly rejected with instructions to convert to XLSX/CSV. Scanned PDF OCR and password-protected PDF extraction are unavailable. PDF extraction reads only the first 50 pages. ExcelJS loads a bounded expanded workbook, then extracts a bounded prefix.
- Worker timeout/cancellation is enforced. Node honors `resourceLimits`; Bun's worker memory enforcement is not established. Before enabling hostile document processing broadly, enforce a service/container process memory limit. Internal parsing worker code is trusted and does not expose an execution tool to the model.
- No Brave key/search spending or generated key/provider was introduced. Supplied-link reading works independently once wired.
- Arbitrary code execution should use an isolated rootless subprocess/container with a read-only runtime, per-chat scratch files only, no credentials/host mounts, no network by default, capped wall time/CPU/memory/output and an explicit supported-language allowlist. Do not reuse the trusted document parser worker as a user-code sandbox.
- Mini-pages should initially be generated static HTML/files in the chat VFS, served only after a separate authorized hosting step with opaque per-chat access, restrictive CSP, sanitized output, and no filesystem routes or server-side execution. No server or hosting/deployment was added here.
